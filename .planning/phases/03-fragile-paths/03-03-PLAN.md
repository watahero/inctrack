<objective>
Stop a saved session of the wrong shape from being applied, and stop a held
timer sync from leaking across a reset.

Purpose: `restore()` checks the version, the instance, whether the run finished
and how old it is -- and then trusts the rest structurally. `objective` and
`next_boss` are adopted by reference; `kills_max`, `objective.count` and
`bonus.max` are never type-checked. Well-formed JSON of the wrong shape reaches
arithmetic in `ui.lua`, and since Phase 2 it reaches arithmetic inside `restore()`
itself, which runs outside any protected call in both of its call sites. And
`State:reset()` clears the run but leaves `pending_time`, so a `/incursion reset`
within thirty seconds of a remaining-minutes line seeds the *next* run's clock
with the old one's number.

Output: a structural validator that rejects rather than coerces and discards
rather than half-applies; `objective` and `next_boss` copied field by field
instead of adopted whole; a one-line fix to `reset()`; the checks for both; and
the phase's closing run.

This is the last plan of Phase 3. It also closes the phase: the whole-phase
verification and the conscious decision on the `right_text` finding are Task 3.
</objective>

    raise -- a raise would escape into an Ashita event handler, which is the

    - **A string where a number belongs is rejected.** One case per numeric
      field that reaches arithmetic: the kill cap, the objective's count, the
      bonus maximum, the remaining bonus seconds, and the saved time left.
    - **A number inside the mob list is rejected**, and so is a nested table

    - **A non-table where a sub-table belongs is rejected**: a string objective,

      list whose second entry has no name discards the entire session, rather
      than restoring a run with one boon.
    - **A blank instance is rejected** -- an empty string is not an instance
      name.
    - **A prior run is not disturbed by a rejection.** With a live run on the
      state, restoring a malformed blob leaves that run exactly as it was; it is
      neither replaced nor cleared.
    - **Everything `serialise()` writes still restores.** A fully populated run
      -- objective with a mob list, next boss, bonus with a countdown, two
      boons, an extras entry, points, awards and a cleared count -- round-trips

    - **The version-1 migration still works**, unchanged: a legacy blob restores,
      its cleared count is re-derived from the phase number, and its award count
      starts at zero.
    - **The version gate still bites**: a blob with an unknown version is
      refused, before and after the validator.
    - **The objective and the boss preview are copies.** Mutating the decoded
      blob after a successful restore does not change the restored run.

    Add a file-local predicate to `inctrack/state.lua` that answers whether a
    decoded blob has the shape a session must have, and call it from `restore()`
    after the version gate and before anything else -- before the wall-clock
    arithmetic, before the migration, before a single field is read for its
    value. A false answer returns false from `restore()` immediately, so the
    session is discarded whole and the state is left exactly as it was found.

    Write it as small helpers over the two questions it keeps asking -- "this is
    absent or a number", "this is absent or a string" -- plus the same for
    booleans, so the body reads as a table of rules rather than a wall of
    conditionals. Reject, never coerce: a field of the wrong type is not
    converted, defaulted or dropped, it fails the whole blob. The reason is the
    project's core value -- a coerced field is a number the server never sent,
    displayed with the same confidence as one it did.

    The rules, derived from what `serialise()` writes rather than invented:

    | Field | Rule |
    |---|---|
    | the blob itself | a table |
    | instance | a string, and not empty |
    | difficulty, finish time | absent or a string |
    | phase, kills seen, kill cap, points, awards seen, cleared count, elapsed, time left, saved-at stamp | absent or a number |
    | finished, points-partial | absent or a boolean |
    | objective | absent, or a table whose kind, name, location and text are each absent or a string, whose count is absent or a number, whose stale marker is absent or a boolean, and whose mob list is absent or a table with positive-integer keys and non-empty string values only |

    | bonus | absent, or a table whose kind, label and location are each absent or a string, whose current, maximum and remaining are each absent or a number, and whose done marker is absent or a boolean |
    | boons | absent, or a table with positive-integer keys whose every value is a table with a non-empty string name and an absent-or-string stats |
    | extras | absent, or a table with string keys whose every value is a table with an absent-or-string label, absent-or-number current and maximum, and an absent-or-boolean done marker |

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the settings JSON on disk -> `State:restore` | a file the player can edit, that a crash can truncate mid-write, and that carries server-supplied strings as both values and table keys; `json.decode` is already protected, the decoded *shape* is not |
| `State:restore` -> the run record -> `ui.lua`'s arithmetic | a field of the wrong type reaches a subtraction or a concat one frame later, inside `d3d_present` |
| `State:restore` -> the Ashita event handlers that call it | both call sites -- the load event and the profile-switch callback -- invoke it outside any protected call, so a raise escapes into the host and, on the settings path, skips the trailing save |
| the player's `/incursion reset` -> the state machine | the one place the player declares a run over; anything that survives it is carried into a run they did not intend it for |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-13 | Tampering | a hand-edited or truncated session blob | high | mitigate | the structural validator runs before any field is read for its value and rejects the whole blob on any type or shape violation; every rejection case asserts the call returned falsy, left no run behind and did not raise |
| T-03-14 | Denial of Service | `restore()` raising inside an Ashita event handler | high | mitigate | the validator runs before the first arithmetic, which is exactly the surface review finding IN-01 recorded; the negative control must include a case that fails by raising, so the protection is known to be doing that job |
