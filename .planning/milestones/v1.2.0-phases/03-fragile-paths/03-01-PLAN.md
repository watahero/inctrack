<objective>
Stop a render error from taking the frame down, sixty times a second, and give
the player a way back.

Purpose: `ui.render` runs inside `d3d_present`, on the game thread, once per
frame. It is handed strings that came off the wire and tables that came out of a
JSON blob. An error thrown between `Begin` and `End` leaves the ImGui window and
style stacks unbalanced -- which does not degrade gracefully, it corrupts
subsequent frames for every addon in the process -- and it then recurs on every
frame after that. The `text_in` handler has been wrapped in a `pcall` since
1.0.0 for exactly this reason; the frame handler never was.

Output: a frame handler that catches the error, repairs the stacks *when a
repair is owed*, says once what happened, disables the window for the session
and names `/incursion` as the way back; a recorder that can be asked to raise
from a nominated ImGui entry point so the second of the phase's two named
triggers is testable at all; and addon-suite checks that pin every one of those
statements -- including the case where the raise precedes the window's opening
and the right repair is no repair.
</objective>

03-CONTEXT.md locks the approach. Do not re-open any of it.

- **The `pcall` goes in `inctrack.lua`'s frame handler, not inside `ui.render`**
  (D: HARD-01). `ui.lua` stays a pure draw function; the host boundary belongs
  in the host-facing module, which is also where the existing `text_in` `pcall`
  lives. One pattern, one place. **`inctrack/ui.lua` is not edited by this plan
  at all.**
- **The ImGui stack is repaired on a caught error**, not left for ImGui to sort
  out. `End()` is called and what was pushed is popped before returning. The
  Phase-1 recorder already counts `Begin`/`End` and push/pop pairs, so this is
  assertable rather than asserted. Repairing what was *not* owed is not part of
  that decision and is forbidden by it in spirit: three statements in
  `ui.render` run before `Begin`, and closing a window that was never opened is
  an unmatched close -- the second error of the frame, not a repair. Task 2
  makes the repair conditional for exactly that reason and Task 2's checks pin
  it.
- **Report once, then disable the window for the session.** The real failure
  mode is sixty identical errors a second. One chat line says what happened and
  names `/incursion`. Silently swallowing is not an option -- a HUD that
  vanishes with no explanation is the quiet wrongness the core value forbids.
- **`/incursion` and `/incursion reset` clear the disabled state**, so the
  player recovers without `/addon reload`.
- Claude's discretion, exercised and now fixed for this plan: the flag is a
  field on the `incursion` table named `render_off`; the bare `/incursion`
  while disabled is a re-enable and a return to automatic visibility, not a
  toggle; the chat line is a single line carrying the error text.

    The repair is conditional, and this is the part of the fix that is easiest
    to get wrong. `render`'s shape is fixed and short -- `state:snapshot()` with
    its early return, the flags arithmetic, one `PushStyleVar`, `Begin`, the
    draws, an unconditional `End`, the pop -- and **three of those statements
    run before `Begin`**. A raise from any of them leaves nothing open and
    nothing pushed, and an `End` there is an unmatched close: on a real host
    that is an ImGui assert, so the repair would become the second error of the
    frame, which is the failure this whole plan exists to prevent. Every
    *data-driven* raise site does sit between `Begin` and the `End`, so when the
    error is one of those exactly one window and one style var are owed -- but
    the shell cannot see inside `render` and must not guess which it is.

    So give it the one fact it can hold honestly: a second boolean on the
    `incursion` table, false at load, named `render_ok`, set true the first time
    the protected call returns cleanly **and** there was a run to draw -- a
    frame that took the early return proves nothing about the window. Guard the
    check so it short-circuits once the latch is set; after the first drawn
    frame it costs nothing. Repair only when `render_ok` is set: the render
    shape has then run end to end on this host at least once, so the constants
    are good, the push and the `Begin` are good, and what raised afterwards is
    inside the window. When it is not set -- the very first render ever
    attempted raised -- repair nothing and go straight to latching and
    reporting. A style var left pushed is recovered when the frame ends; an
    unmatched close is not. `reset()` does not clear `render_ok`: it is a fact
    about the host, not about the run.

    When a repair is owed it means closing the window and popping the style
    variable, in that order, each through its own protected call. Wrapping each
    individually matters for the same reason: neither may become the second
    error of the frame. Do **not** try to repair the style *colour* stack. Its
    only push and pop in the whole file bracket a single ImGui call with no
    data-driven raise between them, so nothing can stop between them; the tests
    assert all three stacks anyway, so if that ever stops being true the suite
    will say so rather than a guess quietly papering over it.

    Write both halves of that reasoning into the comment above the repair -- why
    it is conditional and why the colour stack is left alone -- because it is
    the part of this fix a later reader cannot re-derive from the code. Record
    with it the one residual: the flags arithmetic reads `opts.locked`, so a nil
    ImGui constant reached only on the locked path could raise before `Begin` on
    a host where an unlocked frame has already drawn clean, and there the repair
    would over-close by one window. Nothing data-driven reaches it and no check
    here can provoke it; it is a stated bound, not a defect.

    Latch means setting `render_off`, so the next frame returns at the top.

    Report means one call to the shell's `printf`, producing one chat line that
    carries the error text and names `/incursion` as the way back. Keep the
    error text as a `%s` argument and never as part of the format string --
    a percent sign in server text is exactly what one of the triggers is about.
    Follow the shape the `text_in` handler already uses.

    Then make the two ways back work. In the shell's own `reset(quiet)` local,

    that goes through the same path starts the new character clean. In the
    command handler's bare-subcommand branch, check the field **first**: when it
    is set, clear it, return to automatic visibility by clearing the override,
    print a short line saying the window is back, and return. It is a re-enable,
    not a toggle: toggling against a window that is not being drawn would read
    as "hide it", which is the opposite of what was asked. When the field is not
    set the branch behaves exactly as it does today.

    Leave `visible()` alone. Its override-versus-auto logic is pinned by several
    of the addon suite's 83 checks and the new field is deliberately not part of

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ImGui / the d3d device -> `ui.render` | `render` runs inside `d3d_present`, once per frame, on the game thread; anything it raises is a frame-rate or stack problem for every addon in the process, not a log line |
| server chat text -> the strings the window draws | instance names, mob names and boon stats are quoted straight from the server and can contain any byte, a percent sign included |
| the settings JSON on disk -> the run record `render` walks | a hand-edited or truncated blob reaches the draw tree; structural validation of it is HARD-05, plan 03-03 |
| the player's slash commands -> the addon shell | `/incursion` and `/inc` are the only inputs the player supplies directly, and one of them is now the recovery path |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Denial of Service | `ui.render` inside `d3d_present` | high | mitigate | the protected call plus the stack repair in the frame handler; the window and style-var stacks are asserted balanced after both named triggers, so an unbalanced stack cannot escape into the next frame. The repair is conditional on the render shape having run clean once on this host, so a raise from one of the three statements that precede `Begin` cannot produce an unmatched close -- trigger C asserts nothing is closed there |
| T-03-02 | Denial of Service | chat output on a repeating render failure | high | mitigate | report once and latch; the sixty-frames-after check asserts no further ImGui call and no further chat line, so a systematic failure cannot flood the player's chat at frame rate |
| T-03-03 | Denial of Service | recovery from the latched state | medium | mitigate | `/incursion` and `/incursion reset` both clear it and both are asserted; without a way back the mitigation for T-03-01 would itself be a denial of service |
