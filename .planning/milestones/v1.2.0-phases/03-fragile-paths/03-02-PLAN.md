<objective>
Stop three parser patterns from admitting or mangling things the server never
said -- without any of them reaching past what it does say.

Purpose: the boss-objective split takes the *first* ` at `, so a mob whose own
name contains that substring is truncated and its tail folded into the location.
The mob-list split takes any comma, so a comma-bearing name becomes two phantom
entries rendered verbatim in the window. The boon matcher accepts an empty glyph
group and a blank name. None has been observed to fail; all three are places
where the window would show something the server did not say.

The hazard is the fix, not the fault. A pattern tightened past what the server
actually sends silently drops a real line, which is strictly worse than leaving
it alone. The three tightenings do not all carry the same guarantee, and the
difference decides what an executor should treat as load-bearing:

- **HARD-02 is additive.** The precise greedy, parenthesised form is tried
  first and the shipped 1.1.0 pattern is kept as the fallback at all three call
  sites, so a line that parses today cannot stop parsing whatever the server
  sends tomorrow.
- **HARD-03 and HARD-04 are strict narrowings with no fallback.** The
  comma-space scan replaces the comma-free-run split outright and the non-empty
  glyph group plus the non-blank name test replace the lazy group outright --
  the acceptance criteria require the old shapes to reach zero in the file, so
  there is nothing left underneath. Neither can lose a whole line: HARD-03 only
  changes what a still-parsing line's mob list contains, and HARD-04 narrows a
  tail that no line in the corpus fails. But what stands between them and a
  silent loss is **Task 1's survey**, the exact-11819 structural pin and the
  exact-1 generic pin -- not a fallback branch. The survey is the guard, not a
  formality: a non-zero invariant means the corpus has contradicted a locked
  decision and the plan halts.

Every tightening is accepted on recorded evidence from all 127 logs before it
ships.

Output: `inctrack/parser.lua` with the three patterns tightened -- the boss
split keeping its 1.1.0 shape as a fallback, the list split and the boon tail
narrowed outright on the survey's evidence; a recorded corpus survey; synthetic
checks for each tightening in the adaptability suite; and a new corpus-wide
over-reach guard in the parser suite that recomputes each split from the raw
line in Python.
</objective>
