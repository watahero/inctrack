<objective>
Make the project's own documents describe the addon that actually ships, and
ship it as 1.2.0.

Purpose: `docs/design.md` is the ground-truth record of the server message
stream and of what the addon does with it. It currently says the window is fixed
width rather than auto-resizing (it is the other way round), that the count of
points messages is the count of cleared phases (the defect FIX-01 removed), and
that there are seven suites (there are ten). It does not mention schema version
2, the structural validator, the render containment, or any of the three parser
tightenings. `README.md` describes a smaller test suite than the one that ships
and a corpus that has grown. `addon.version` reads `1.1.0`. And `ui.lua`'s
layout comment shows one sample window out of the seven shapes the code can
draw.

The rule for the whole plan: **verify every claim against the source before
writing it down.** Two of Phase 3's summaries open with a SUPERSEDED note --
the code review reversed two decisions after they were written -- so a document
built from the summaries would ship two statements that are false about the
code.

Output: the version, the changelog and the README corrected; the design document
rewritten to describe the shipped code; the layout comment brought up to date;
a harness pin so the version and the changelog cannot drift apart again; and the
milestone's closing run and redeploy.
</objective>
